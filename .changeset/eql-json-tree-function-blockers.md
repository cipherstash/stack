EQL v4 `json_tree`: calling a native jsonpath or extraction function on a `public.eql_v4_json_search` column, or on an entry extracted from one, now raises `feature_not_supported` (SQLSTATE `0A000`) instead of returning nothing (#1439).

The column is a domain over `jsonb`, so `jsonb_path_match(col, $1::jsonpath, $2::jsonb)` used to resolve to PostgreSQL's own function, which ran over the stored ciphertext envelope rather than the document and returned false for every row, with no error. EQL now installs overloads in `public` for `jsonb_path_exists`, `jsonb_path_match`, `jsonb_path_query`, `jsonb_path_query_array` and `jsonb_path_query_first` (and their `_tz` forms), `jsonb_extract_path`, `jsonb_extract_path_text`, `jsonb_each`, `jsonb_each_text`, `jsonb_object_keys`, `jsonb_typeof`, `jsonb_strip_nulls`, `jsonb_set`, `jsonb_insert` and `jsonb_pretty` on both `public.eql_v4_json_search` and `public.eql_v4_json_entry`. Each raises with a message naming the function and what to do instead. On a document, the jsonpath and extraction blockers name the EQL query to use (`@>` with an `eql_v4.query_json` needle, `col -> selector`, or a subtree walk), and `jsonb_typeof`, `jsonb_set`, `jsonb_insert`, `jsonb_strip_nulls` and `jsonb_pretty` direct the caller to decrypt the document in the client. On an entry, `jsonb_path_exists` and `jsonb_path_match` name the comparison with an `eql_v4.query_json_leaf`, and the others direct the caller to decrypt in the client.

Two limits, documented in `docs/reference/json-tree-leakage.md`. A call is caught only when every argument has a type: a bare literal (`jsonb_path_match(col, '$.a == 1')`) or a parameter sent without a type still reaches the native function, so cast every argument. And with the `eql_v4` bundle installed, a call to any of these 20 functions whose first argument is an untyped literal or an untyped bound parameter now fails with `function … is not unique` (SQLSTATE `42725`), on plain `jsonb` too: `jsonb_typeof('{}')`, `jsonb_typeof($1)`, `jsonb_path_exists($1, '$.a')`. Cast the first argument to `jsonb`; a `jsonb` column or a parameter typed `jsonb` is unaffected. See [U-004](../../docs/upgrading/v3.1.md#u-004-an-untyped-first-argument-to-20-jsonb-functions-is-ambiguous).
