# fix(deps): patch vitest to 4.1.11

Patches CVE-2026-84373 in `vitest` / `@vitest/mocker` (patched in 4.1.11).

- `@cipherstash/auth` and `@cipherstash/profile` declared `vitest: ^3` directly, which resolved 3.2.7 (with `@vitest/mocker` 3.2.7). Both now use `catalog:repo`, which already pins `vitest` and `@vitest/coverage-v8` to 4.1.11, like every other workspace package.
- The lockfile drops the whole 3.2.7 tree; `vitest` and `@vitest/mocker` resolve only 4.1.11.
- Fixes the `require-auth-npm-changeset` check, which required an `@cipherstash/auth` changeset for any change under the package, tests and devDependencies included. Merging such a changeset rebuilds and republishes all seven auth packages with nothing new in them. The check script now has a `--shipped` mode that the workflow passes the changed paths through. It ignores files no published package contains (`__tests__/`, `examples/`, `vitest.config.ts`, `tsconfig.json`) and `package.json` changes that touch only `devDependencies`. Any path it doesn't recognise still needs a changeset.
- With the check fixed, this PR no longer needs its auth changeset, so it is removed. It would have published an empty release and named a CVE in the public changelog that never affected the published package.

### Verification

- `check-auth-npm-changeset.test.mjs` and `workflow-paths-filter-parity.test.mjs` pass (59 tests). The new tests cover the path filter, the `--shipped` command against real git history, and the workflow wiring.
- Breaking the filter on purpose (dropping the devDependencies rule; loosening the `__tests__/` prefix) fails the tests.
- Run against this branch, the only auth path changed is `languages/typescript/packages/auth/package.json`, and `--shipped` reports nothing, so the check passes without a changeset.
