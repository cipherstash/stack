# Use the generated sqlc package with the encrypted type

This example is the database package that [sqlc](https://github.com/sqlc-dev/sqlc) generates for the [`users` example](../../users/README.md).
Its structs match `users.EncryptedUser`, so the store uses Go conversions instead of field copies.
The generated fields use planned Encrypt Query Language (EQL) types.
The Golang SDK for CipherStash Stack is planned and does not exist yet, so this code does not build in this repository.
The [Go example index](../../README.md) lists every example and what was checked.

## What you will learn

- Generate the sqlc package again without editing generated code.
- Convert sqlc's row struct and parameters to the encrypted type.
- Use the generated methods from the users store.

## Generate the sqlc package again

- **Purpose:** Identify the generator, its version, and the command that generates the package again.
- **Related:** [The sqlc inputs](../../sqlc/README.md)
- **Needs:** Nothing

sqlc v1.31.1 generated `db.go`, `models.go`, and `query.sql.go`.
Run `sqlc generate` in [`sqlc/`](../../sqlc/) to generate them again.
A person must not edit these files.

[`db.go`, lines 1 to 5](db.go#L1-L5)

```go
// Code generated by sqlc. DO NOT EDIT.
// versions:
//   sqlc v1.31.1

package userdb
```

## Convert generated structs by shape

- **Purpose:** See why direct Go conversions connect sqlc to the encrypted type.
- **Related:** [The plan's model design](../../../2026-10-04-plan-builder.md#models), [the users sqlc store](../../users/README.md)
- **Needs:** Know that an encrypted type has one field for each stored field.

sqlc's row struct `userdb.User` has the same fields as `users.EncryptedUser`.

[`models.go`, lines 11 to 15](models.go#L11-L15)

```go
type User struct {
	ID    int64
	Email eql.TextEq
	Name  eql.TextEq
}
```

`CreateUserParams` has the same shape too.

[`query.sql.go`, lines 18 to 22](query.sql.go#L18-L22)

```go
type CreateUserParams struct {
	ID    int64
	Email eql.TextEq
	Name  eql.TextEq
}
```

Go ignores struct tags during struct conversion in Go 1.8 and later.
The `db` and `gorm` tags on `users.EncryptedUser` therefore do not stop either conversion.
The users store converts with `EncryptedUser(row)` and `userdb.CreateUserParams(e)`.
A field change stops either conversion from compiling until both shapes agree.

## Use the generated methods

- **Purpose:** Connect generated identifiers to the handwritten users store.
- **Related:** [The users sqlc store](../../users/README.md), [the sqlc queries](../../sqlc/query.sql)
- **Needs:** Understand the matching struct shapes.

`userdb.New` creates `Queries`, and `WithTx` binds the methods to a transaction.
The users store calls `CreateUser`, `GetUser`, and `FindUsersByEmail`.

[`db.go`, lines 19 to 31](db.go#L19-L31)

```go
func New(db DBTX) *Queries {
	return &Queries{db: db}
}

type Queries struct {
	db DBTX
}

func (q *Queries) WithTx(tx *sql.Tx) *Queries {
	return &Queries{
		db: tx,
	}
}
```

The examples do not use the generated `ListUsers` method.

## What was checked

- **Every Go file type-checks:**
  Run.
  `go vet ./...` passes against a stub of the SDK.
  The stub is not in this repository, and it has signatures only.
- **sqlc's row struct converts to the generated type:**
  Run.
  The conversions in `users/sqlcstore.go` compile against real sqlc output.
- **The SDK can be built with these signatures:**
  Not run.
- **The code works with a database, GORM or pgx:**
  Not run.
  Nothing here has connected to a database.
- **The EQL types, and the value the guest returns for them:**
  Not run.
  `eql-codegen` does not write Go yet, and the examples use a stub of `eql.TextEq`.
