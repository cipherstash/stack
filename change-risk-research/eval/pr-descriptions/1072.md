# ci(tests): skip Test JS on PRs that change only docs/plans

## What
Stop the "Test JS" workflow from running on pull requests that change only files under `docs/plans/`. Pushes to `main` still run everything.

## Why
A documentation-only plan PR ran every Node, Bun, Deno and E2E job. Nothing in those jobs reads `docs/plans/`, once one test row that read a single plan is removed.

## How
- `pull_request` in `tests.yml` gets `paths: ['**', '!docs/plans/**']`. It is an ignore-list on purpose: the `test:scripts` step reads nearly every tracked file, so an honest allowlist is the whole repo, and an ignore-list can only err toward running too much.
- The one test row that read a plan (`frozen-publisher-docs.test.mjs`) is removed, and the `AGENTS.md` sentence that named the plan is updated. The freeze it guarded ended when EQL left `FROZEN_PUBLISHERS`. `AGENTS.md` and `SECURITY.md` keep their rows.
- Three guards (auth binding, protect-ffi/WASM build inputs, protect-ffi trigger scope) read a filter as a list of positive globs, so they could not read the new one. They now share a helper that applies GitHub's semantics: in order, last match wins, `**` selects everything, `!` removes. A negation that might overlap an input counts as removing it. I mutated the filter to remove each input and ran each guard, and each still fails. The change to how three guards read a filter deserves a careful review.
- `tests.yml` is added to the expected asymmetries in the parity test, because `push` is unfiltered.
- Known gap: three checks scan by file type wherever the file is (Biome for JS/TS/JSON/CSS, a test that reads every `*.sh`, and the EQL-pin lint that reads every `Cargo.toml` and `package.json`), so a file of one of those types added under `docs/plans/` would skip them.
- Not tested live. For a `pull_request`, GitHub uses the workflow file from the PR's own branch, so this PR itself is the first real exercise of the filter.
