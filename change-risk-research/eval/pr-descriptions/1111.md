# fix(ci): key the mise cache by runner image

## Summary

CI on PR #1094 fails in four Rust jobs before any test runs: `cargo-nextest: GLIBC_2.38 not found`. Nothing is wrong with the code. Some CI jobs run on Ubuntu 22.04 and some on Ubuntu 24.04, and they share one cached copy of the Rust test tools. A tool built on 24.04 does not run on 22.04. This PR gives each Ubuntu version its own cache.

## Changes

- **Workflows:** every cached `jdx/mise-action` step (31 of them, across 14 workflows) sets `cache_key_prefix: mise-v1-ubuntu-2204` or `mise-v1-ubuntu-2404`, matching its job's `runs-on`.
- **Guard:** `scripts/__tests__/workflow-mise-cache-image.test.mjs` fails when a cached mise step's prefix does not name its job's image. A job whose `runs-on` names no image (a matrix, `ubuntu-latest`) must set `cache: false`.

## How the bug happens

- **What mise does:** mise installs the tools pinned in `mise.toml` and `mise.test.toml`. The `cargo:` tools (nextest, llvm-cov, crap, mutants, fuzz, udeps) are compiled on the runner that installs them, so they link that runner's glibc.
- **Why the cache is shared:** `mise-action` saves the installed tools under a key built from the OS (`linux-x64`), the mise version, the env and a hash of the mise config. Ubuntu 22.04 and 24.04 get the same key.
- **Why it shows up only sometimes:** whichever job saves a new key first decides which glibc the cached tools need. A key is new only when the mise config changes. `main`'s entry was saved by a 22.04 job and works. PR #1094 changes `mise.toml`, its `fuzz` and `udeps` jobs (24.04) saved the new key first, and the 22.04 jobs (`tests-crates`, `crap-crates`, `tests-golang`) then failed. A re-run restores the same entry.
- **Why the old keys go away:** changing the prefix also moves every job off the bad entry.

## Verification

- `pnpm test:scripts`: 70 files, 1252 tests passed, 29 skipped.
- With the workflow edits reverted, the new guard fails and names each step.
- `pnpm code:check` has no errors.
- The runner glibc versions come from the failing #1094 logs (`ldd` reports 2.35 on `blacksmith-16vcpu-ubuntu-2204`) and the `GLIBC_2.38`/`GLIBC_2.39` errors there.
